# BlackBoxRS: Architecture Pivot

This document defines the new core domain, subsystems, and data flow that
turn BlackBoxRS from "telemetry daemon" into "incident intelligence and
prevention system." Read alongside `PIVOT_BRIEF.md`.

Conventions:
- **Required** = must be present for the bundle to be valid.
- **Optional** = present when available; bundle is still valid without it.
- **Source of truth** = where the value originates. The same value never
  has two authoritative sources.
- All schema sketches are pydantic v2 models; the dataclass-based config
  module stays as is.

---

## 1. Core domain objects

### 1.1 `Incident`

**Purpose.** Top-level identity for a single failure, recurrence, or
manual investigation. The thing engineers attach to a bug report.

**Required fields:**
- `incident_id: str`: short, opaque, time-prefixed, e.g. `inc_2026-05-07T14-22-13_a3f2`.
- `created_at: datetime` (UTC, ISO 8601). Time the incident was *built*.
- `window_start: datetime`: first event included in the bundle.
- `window_end: datetime`: last event included in the bundle.
- `session_id: str`: the BlackBoxRS session that produced the evidence.
  Cross-session incidents are explicitly multi-session (see `sessions`).
- `severity: Literal["info","warning","error","critical"]`: derived from
  highest-severity event in the bundle, overridable by the user.
- `title: str`: short human-readable summary (≤ 120 chars).
- `summary: str`: one-paragraph plain text. Generated by report builder
  but stored so the JSON is self-describing.
- `bundle_path: str`: local path to the on-disk bundle directory.
- `schema_version: str`: `"1.0"`, bumps on breaking JSON changes.

**Optional fields:**
- `tags: list[str]`: free-form, e.g. `["customer-escalation","tf"]`.
- `sessions: list[str]`: additional session IDs (multi-session incidents).
- `triggers: list[str]`: `DetectorTrigger.trigger_id` references.
- `fingerprint: FailureFingerprint | None`: assigned at build time; can
  be re-computed.
- `likely_causes: list[LikelyCauseHypothesis]`: ranked hypotheses with
  evidence references.
- `linked_prevention_rules: list[str]`: `PreventionRule.rule_id`s.
- `notes: str | None`: free-form engineer commentary.
- `host: str`: hostname where evidence was captured.

**Source of truth.** The bundle directory on disk is canonical;
`incident.json` is the index. The local incident store reads/writes that
JSON and never mutates the bundle in place.

**Storage format.** `incident.json` (canonical), with a sibling
`report.md` rendered for humans.

**Relation to existing data.** Subsumes the existing event stream: the
events that fall inside `[window_start, window_end]` plus the matched
`anomaly_engine` events form the evidence corpus.

---

### 1.2 `EvidenceBundle`

**Purpose.** The on-disk artifact. Self-contained: every claim in
`report.md` resolves to an evidence file in this directory.

**Required layout:**
```
incident_<id>/
  incident.json               # Incident object
  report.md                   # human-readable rendering
  timeline.json               # ordered list of TimelineEvent
  evidence/
    events.jsonl              # raw BlackBoxEvent stream within window
    snapshots.json            # SystemSnapshot list (sampled)
    triggers.json             # DetectorTrigger list
  signatures/
    config.json               # ConfigSignature
    versions.json             # VersionSignature
  attachments/                # optional, may be absent
    rosbag2_*/                # rosbag2 directories from Rosbag2Recorder
    journal_*.txt             # journalctl excerpts (optional)
  fingerprint.json            # FailureFingerprint
```

**Required content:**
- `incident.json`, `report.md`, `timeline.json`,
  `evidence/events.jsonl`, `signatures/config.json`,
  `signatures/versions.json`, `fingerprint.json`.

**Optional content:**
- `evidence/snapshots.json`, `evidence/triggers.json`,
  `attachments/`, `notes.md`.

**Source of truth.** The directory itself. Tools (`incident show`,
`incident replay`) read it without needing the daemon to be running.

**Storage format.** Plain files; no database. Optional `bundle.tar.gz`
sibling created by `incident pack` for distribution.

**Relation to existing data.** `evidence/events.jsonl` is a *slice* of
the existing rotating JSONL. We re-write it into the bundle so the
bundle survives independently of `~/.blackboxrs/logs/`.

---

### 1.3 `TimelineEvent`

**Purpose.** A single point on the incident timeline. Distinct from the
raw `BlackBoxEvent` because it carries derivation metadata and ordering.

**Required fields:**
- `t: datetime`: UTC timestamp; copied from source event when raw,
  computed when derived.
- `kind: Literal["raw","derived","trigger","snapshot","external"]`.
- `subsystem: Literal["ros","system","gpu","anomaly","recorder","config","external"]`.
- `summary: str`: short label, e.g. `"frequency drop on /scan"`.
- `confidence: float` (0.0–1.0): 1.0 for raw, lower for derived.
- `evidence_ref: str`: pointer like `events.jsonl#L42` or
  `triggers.json#trigger_id`. Always resolvable inside the bundle.

**Optional fields:**
- `data: dict[str, Any]`: minimal extra payload (avoid duplicating
  raw event data; keep that in `events.jsonl`).
- `correlated_event_refs: list[str]`: back-references for derived events.
- `causality_hint: Literal["precursor","consequence","independent"] | None`.

**Source of truth.** Built from `events.jsonl` + `triggers.json`. Never
edited by hand inside the bundle.

**Storage format.** `timeline.json`: JSON list, ordered by `t` ascending.

**Relation to existing data.** Each `TimelineEvent` has at most one
backing `BlackBoxEvent`. Derived events (e.g. "topic /scan went silent
for 3.2s") are explicitly marked `kind="derived"` and carry a list of
`correlated_event_refs`.

---

### 1.4 `DetectorTrigger`

**Purpose.** A first-class record of when an anomaly detector fired.
Already exists implicitly as `event.source == "anomaly_engine"`; we
promote it to a typed model.

**Required fields:**
- `trigger_id: str`: `trg_<sha8>` deterministic from
  `(detector, t, subject)`.
- `detector: str`: `name` from `BaseDetector`.
- `detector_class: str`: fully qualified Python class for
  fingerprinting and reproducibility.
- `t: datetime`.
- `subsystem: str`: same enum as `TimelineEvent.subsystem`.
- `subject: str`: what triggered: a topic, metric, or node name.
- `severity: Literal["info","warning","error","critical"]`.
- `message: str`.
- `data: dict[str, Any]`: observed value, threshold, etc.

**Optional fields:**
- `signature_fields: list[str]`: names of `data` keys that count
  toward the failure fingerprint.
- `source_event_ref: str`: `events.jsonl#L<n>` of the original
  `anomaly_engine` event.

**Source of truth.** Re-derived from the anomaly events in
`events.jsonl`. Stored in `evidence/triggers.json` for fast access.

**Storage format.** JSON list.

**Relation to existing data.** A 1:1 promotion of existing
`BlackBoxEvent(source="anomaly_engine")` events into a typed model
(no information loss).

---

### 1.5 `SystemSnapshot`

**Purpose.** A point-in-time picture of the system: graph + host + GPU.
Used for incident reconstruction and for fingerprinting "what state was
the system in when this happened."

**Required fields:**
- `t: datetime`.
- `host: str`.
- `cpu_percent: float`.
- `mem_percent: float`.
- `topics: list[TopicSnapshot]`: `name`, `msg_type`, `pub_count`,
  `sub_count`, `last_freq_hz`, `qos_summary`.
- `nodes: list[str]`: fully-qualified node names.

**Optional fields:**
- `disk_percent: float | None`, `disk_io: dict | None`.
- `thermal_zones: dict[str, float] | None`.
- `gpu: GPUSnapshot | None`: `util_percent`, `mem_percent`,
  `temp_c`, `power_w`.
- `processes: list[ProcessSnapshot] | None`: top N by CPU/mem.

**Source of truth.** New `core.snapshots.SystemSnapshotter` polls at a
configurable cadence (default 5 s during normal operation, 1 s within
an "incident watch" window after a trigger fires).

**Storage format.** `evidence/snapshots.json`: list of snapshots,
ordered by `t`.

**Relation to existing data.** Re-uses outputs from `system_monitor`
and `ros_monitor`. We do *not* invent new collectors; we project what
the existing monitors already produce into a typed snapshot at fixed
intervals.

---

### 1.6 `ConfigSignature`

**Purpose.** The reproducibility hash of *how the robot was configured
at the moment of the incident.* Without this, the bundle is not
reproducible.

**Required fields:**
- `t: datetime`: capture time (usually session start).
- `hash: str`: sha256 of the canonicalized payload, hex-encoded.
- `payload: dict[str, Any]`: the structure that was hashed:
  - `ros_distro: str | None`
  - `ros_domain_id: int | None`
  - `rmw_implementation: str | None`
  - `launch_files: list[{path: str, sha256: str}]` (optional;
    captured when the user runs `robot-blackbox attach-launch`)
  - `parameter_files: list[{path: str, sha256: str}]`
  - `urdf_files: list[{path: str, sha256: str}]`
  - `env_subset: dict[str, str]`: whitelisted vars
    (`ROS_*`, `RMW_*`, `LD_LIBRARY_PATH`, `PYTHONPATH`, etc.)
  - `blackboxrs_config_yaml_sha256: str`

**Optional fields:**
- `git_commits: dict[str, str]`: repo path → HEAD sha for any
  workspace dirs the user attached.

**Source of truth.** Captured at session start by a new
`core.signatures.ConfigSignatureCollector`. Hashes are deterministic
under canonical JSON serialization.

**Storage format.** `signatures/config.json`.

**Relation to existing data.** New. No equivalent today.

---

### 1.7 `VersionSignature`

**Purpose.** *What software was running.* Pairs with `ConfigSignature`
to fully describe the run.

**Required fields:**
- `t: datetime`.
- `hash: str`: sha256 of canonicalized payload.
- `payload`:
  - `os: {name, version, kernel}` (e.g. Ubuntu 22.04, 6.8.0-111-generic)
  - `python: {version, executable}`
  - `ros_distro: str | None`
  - `ros_packages: list[{name, version}]` (apt + pip; deduped by name)
  - `nvidia_driver: str | None`
  - `cuda: str | None`
  - `blackboxrs_version: str`

**Optional fields:**
- `dpkg_subset: list[{name, version}]`: narrow whitelist
  (`ros-*`, `python3-*`, `nvidia-*`, `linux-image-*`).
- `pip_freeze_sha256: str`: for full reproducibility without bloating
  the bundle.

**Source of truth.** `core.signatures.VersionSignatureCollector`.
Slow-path collection is gated to once per session.

**Storage format.** `signatures/versions.json`.

**Relation to existing data.** New.

---

### 1.8 `FailureFingerprint`

**Purpose.** A stable identifier for "this *kind* of failure." Two
incidents with the same fingerprint should usually share root cause.

**Required fields:**
- `fingerprint_id: str`: `fpr_<sha16>`, deterministic from
  the canonical payload.
- `algorithm_version: str`: `"v1"`. Bumps when scheme changes.
- `payload`:
  - `detector_classes: list[str]`: sorted, unique.
  - `subsystems: list[str]`: sorted, unique, derived from triggers.
  - `signature_fields: dict[str, Any]`: detector-declared fields
    pulled from each trigger. (See "Failure fingerprinting" §5.)
  - `topology_signature: str | None`: short hash of (set of topics
    that went silent or had QoS mismatch), order-independent.

**Optional fields:**
- `cluster_id: str | None`: assigned by clustering (out of scope for
  v0.4 MVP; reserved).
- `human_label: str | None`: user-edited.

**Source of truth.** Computed by `core.fingerprint.compute()` from
`triggers.json` + `timeline.json`. Stored in `fingerprint.json`.

**Storage format.** `fingerprint.json`.

**Relation to existing data.** New.

---

### 1.9 `PreflightCheck`

**Purpose.** A *check* that runs before launch and asserts that the
system is in a state that has historically not produced this failure.
Distinct from `PreventionRule`, which is the *origin* of the check.

**Required fields:**
- `check_id: str`.
- `name: str`.
- `kind: Literal["topic_present","qos_match","node_running","env_var",
  "param_value","resource_threshold","custom_python"]`.
- `params: dict[str, Any]`: keyword arguments for the check.
- `severity_on_fail: Literal["warn","block"]`.
- `message_template: str`: formatted with the params on failure.

**Optional fields:**
- `applies_to: list[str]`: robot/host tags.
- `produced_by: str | None`: `PreventionRule.rule_id`.

**Source of truth.** `prevention/checks.yaml` (user-editable) +
auto-generated rules in `prevention/auto/<rule_id>.yaml`.

**Storage format.** YAML files; loaded into typed models at runtime.

**Relation to existing data.** New.

---

### 1.10 `PreventionRule`

**Purpose.** Encodes "the *reason* this check exists." Closes the
loop from incident → prevention.

**Required fields:**
- `rule_id: str`: `rule_<sha8>`.
- `created_at: datetime`.
- `source_incident_id: str`: incident this rule was derived from.
- `source_fingerprint_id: str`: fingerprint the incident matched.
- `check: PreflightCheck`: the actual check definition.
- `rationale: str`: short narrative ("incident inc_… showed /scan
  silenced after a QoS mismatch on subscriber side; preflight asserts
  reliability=BEST_EFFORT on /scan").

**Optional fields:**
- `disabled: bool = False`.
- `last_fired: datetime | None`.
- `fire_count: int = 0`.

**Source of truth.** `~/.blackboxrs/prevention/rules/<rule_id>.yaml`.

**Storage format.** YAML.

**Relation to existing data.** New.

## 2. Major subsystems

### 2.1 Telemetry capture (existing, retained)

`ros_monitor`, `system_monitor`, `anomaly_engine`, `recording`,
`logging` are kept as-is. They form the **evidence layer**.

Changes:
- `anomaly_engine` is extended (additively) so that detectors *declare*
  a `signature_fields` list. Existing detectors stay backward compatible
  (default: empty list).
- `system_monitor` gains a thin `SystemSnapshotter` projection that
  consumes its existing events and emits typed `SystemSnapshot`s.

### 2.2 Incident builder (new)

Module: `blackboxrs/incident/builder.py`.

Inputs:
- A time window `(window_start, window_end)`.
- Optional list of `BlackBoxEvent`s (when called in-process at trigger
  time) or, more commonly, a `LogReader` over `~/.blackboxrs/logs/`.
- Optional override `session_id`.

Outputs:
- A complete `EvidenceBundle` directory.
- An `Incident` object persisted as `incident.json`.

Pipeline (deterministic, single-pass):
1. Resolve session metadata.
2. Slice events from the log directory into `events.jsonl`.
3. Promote anomaly events into typed `DetectorTrigger`s →
   `triggers.json`.
4. Project periodic snapshots → `snapshots.json`.
5. Capture / load `ConfigSignature` and `VersionSignature` → `signatures/`.
6. Run timeline reconstructor → `timeline.json`.
7. Compute `FailureFingerprint` → `fingerprint.json`.
8. Run likely-cause analyzer → fill `Incident.likely_causes`.
9. Render `report.md` from the structured incident.
10. Write `incident.json`.

The pipeline is idempotent: re-running on the same inputs produces the
same bundle (modulo `created_at`, which is stable when given).

### 2.3 Timeline reconstruction engine (new)

Module: `blackboxrs/incident/timeline.py`.

Responsibility:
- Read `events.jsonl` + `triggers.json`.
- Order events strictly by timestamp; break ties by source priority
  (`anomaly_engine` > `ros_monitor` > `system_monitor` > everything else).
- Produce derived events:
  - **silence interval**: contiguous gap > `dead_topic.timeout_sec`
    on a topic that previously had data.
  - **resource excursion**: sustained
    `cpu_percent > anomaly.thresholds.cpu_percent` for ≥ 3 s.
  - **graph delta**: appearance/disappearance of nodes or topics
    between consecutive `system_snapshot` events.
- Annotate each event with `confidence` (raw events: 1.0; derived:
  algorithm-specific; defaults below).
- Annotate causality hints by *temporal-correlation* heuristic only:
  for each trigger, look back ≤ 30 s; mark any earlier derived event as
  `causality_hint="precursor"` and any event within 30 s after as
  `consequence`. This is a heuristic, not a proof. Stored confidence
  reflects that.

Default confidences:
- Raw `BlackBoxEvent`: 1.0
- `silence interval`: 0.95 (deterministic from data).
- `resource excursion`: 0.85 (sensitive to sampling jitter).
- `graph delta`: 0.85.
- Causality hint annotations: do not change confidence; they are a
  separate annotation layer.

### 2.4 Config / version differ (new)

Module: `blackboxrs/incident/diff.py`.

Responsibility:
- Compare current run's `ConfigSignature` / `VersionSignature` against
  the prior session's.
- Highlight:
  - Differing `ros_distro`, `rmw_implementation`, `ros_domain_id`.
  - Changed launch / parameter / URDF file hashes.
  - New / removed / version-changed `ros_packages`.
- Output a `ConfigDiff` block embedded in the report when relevant.

Used both at incident-build time (was the config different from last
session?) and at preflight time (is the about-to-launch config compatible
with the prevention library?).

### 2.5 Incident report generator (new)

Module: `blackboxrs/incident/report.py`.

Responsibility:
- Render `report.md` from the structured `Incident` + bundle contents.
- The report is **terse, technical, accountable**. Sections:
  1. **Header**: id, severity, window, host, session.
  2. **Summary**: one paragraph, generated.
  3. **Timeline**: markdown table, max 50 rows; `t`, subsystem, summary.
     Truncation explicit.
  4. **Triggers**: every `DetectorTrigger`, with subject + observed
     value + threshold + message.
  5. **Likely causes**: ranked list with confidence and the
     `evidence_ref`s that support it.
  6. **Config / version signatures**: short summary + diff vs. previous
     session if relevant.
  7. **Fingerprint**: id and a one-line description of what defines it.
  8. **Recommended preflight rule**: pre-rendered YAML the user can
     adopt with one CLI command.
  9. **Attachments**: list of files in `attachments/` with sizes.

The report does *not* speculate. Every claim links to a file and line
range in the bundle.

### 2.6 Failure fingerprint clustering (out of scope for v0.4 MVP)

For v0.4 we ship deterministic *single-incident* fingerprinting only.
Cross-incident clustering becomes a separate command in v0.5:

```
robot-blackbox incident cluster --since 30d
```

Reserved interface: a `cluster_id` field exists on
`FailureFingerprint`; v0.4 leaves it `None`.

### 2.7 Preflight prevention engine (new, MVP scaffold)

Module: `blackboxrs/prevention/`.

Components:
- `rules.py`: `PreventionRule`, `PreflightCheck` models, YAML loader.
- `checks/`: `topic_present.py`, `qos_match.py`, `node_running.py`,
  `env_var.py`, `param_value.py`, `resource_threshold.py`. Each is a
  function with a typed `params` model.
- `runner.py`: `PreflightRunner.run()` returns a structured report
  with `pass / warn / block` per check.
- `cli` integration via `robot-blackbox preflight`.

For v0.4 we ship the runner, the YAML loader, and three concrete
check kinds: `topic_present`, `qos_match`, `node_running`. The other
kinds are stubs with TODOs.

### 2.8 Dashboard / API layer (deferred)

No web dashboard in v0.4. The CLI renders reports; bundle files are
hand-readable. We *do* expose an importable Python API
(`blackboxrs.incident.api`) with `build_incident()`, `load_bundle()`,
`render_report()` so other tools (or a later web UI) can integrate.

### 2.9 Replay artifact packaging interface (new, narrow)

Module: `blackboxrs/incident/pack.py`.

Two operations:
- `pack(bundle_dir) -> tar.gz`: deterministic ordering, embedded
  manifest, optional gzip.
- `unpack(archive) -> bundle_dir`: verifies manifest, refuses to
  overwrite.

We do *not* try to re-run the robot. "Replay" in v0.4 means "open the
bundle and re-derive the report." Time-aligned ROS replay is a v0.6
topic and depends on rosbag attachments.

## 3. Data flow

```
┌──────────────────────────────────────────────────────────────────┐
│                    blackboxrs daemon (existing)                  │
│                                                                  │
│  ros_monitor ─┐                                                  │
│  system_mon ──┼─► event_bus ─► anomaly_engine ─► event_bus       │
│  recording ───┘                                                  │
│                                                                  │
│              event_bus ─► logging.RotatingJsonlWriter            │
│                                          │                       │
│                                          ▼                       │
│                            ~/.blackboxrs/logs/*.jsonl            │
└──────────────────────────────────────────────────────────────────┘
                                          │
                  on demand or auto-trigger│
                                          ▼
┌──────────────────────────────────────────────────────────────────┐
│                  blackboxrs incident build                       │
│                                                                  │
│  LogReader(window) ──► IncidentBuilder                           │
│                          │                                       │
│                          ├─► writes events.jsonl                 │
│                          ├─► promotes anomaly events → triggers  │
│                          ├─► snapshotter → snapshots.json        │
│                          ├─► signatures (config + versions)      │
│                          ├─► timeline.reconstruct → timeline     │
│                          ├─► fingerprint.compute → fingerprint   │
│                          ├─► likely_causes.rank → incident.json  │
│                          ├─► report.render → report.md           │
│                          └─► (optional) pack → bundle.tar.gz     │
└──────────────────────────────────────────────────────────────────┘
                                          │
                                          ▼
                ~/.blackboxrs/incidents/inc_<...>/
                                          │
                                          ▼
┌──────────────────────────────────────────────────────────────────┐
│                 blackboxrs preflight (next launch)               │
│                                                                  │
│  prevention/rules/*.yaml ──► PreflightRunner                     │
│                                │                                 │
│                                ├─► topic_present checks (rclpy)  │
│                                ├─► qos_match checks   (rclpy)    │
│                                ├─► node_running checks(rclpy)    │
│                                └─► env / param checks            │
│                                                                  │
│  exit 0 if all checks pass; exit 1 if any blocking check fails;  │
│  exit 2 on warnings (configurable).                              │
└──────────────────────────────────────────────────────────────────┘
```

Key invariants:

- The **daemon** never knows about incidents. It writes events. The
  incident builder is a *consumer* of those events. This keeps capture
  cheap and lets incident logic evolve without touching hot paths.
- The **bundle** is the unit of currency. Every other operation
  (preflight, clustering, replay) is a function over bundles.
- The **prevention library** is an append-only set of YAML files; never
  hidden state. Anything BlackBoxRS will block on must be a file the
  user can read, edit, and disable.

## 4. Decisions

### A. Incident bundle format

Decided: **directory of plain files**, JSON for structured data,
markdown for the report, optional rosbag2 directories under
`attachments/`. Optional `bundle.tar.gz` companion via `incident pack`.

Why: maximum portability, no DB lock-in, hand-readable, diffable in
git, attachable to JIRA. Trade-off: many small files. Acceptable ,
bundles are not high-frequency artifacts.

### B. Timeline model

Decided as in §2.3. Three event kinds (`raw`, `derived`, `trigger`
plus `snapshot` and `external`). Strict timestamp ordering with source
priority for ties. Confidence is mandatory and reflects derivation.
Causality is annotated, not asserted.

### C. Root-cause hypothesis support

Grounded approach. We rank `LikelyCauseHypothesis` objects via:
- detector class weight (e.g. `QoSMismatchDetector` outranks
  `ThresholdDetector` for "no data on topic" symptoms);
- temporal proximity to the highest-severity trigger;
- presence of a precursor in `ConfigDiff` (recent config change);
- recurrence: this fingerprint matches an earlier closed incident.

Each hypothesis carries:
- `cause: str`: human-readable label.
- `confidence: float` (0.0–1.0).
- `evidence_refs: list[str]`: every source that contributed.
- `caveat: str | None`: explicit note when confidence < 0.5.

We **never** display a single "the cause is X" line. We display a
ranked list with confidence and evidence. The report can promote the
top hypothesis to the summary only if its confidence ≥ 0.7.

### D. Failure fingerprinting (v1)

Deterministic. The fingerprint payload is:

```python
{
  "detector_classes": sorted(set(t.detector_class for t in triggers)),
  "subsystems":      sorted(set(t.subsystem      for t in triggers)),
  "signature_fields": {
      detector_class: sorted([
          (k, normalize(v))
          for trigger in detector_triggers
          for k, v in trigger.data.items()
          if k in trigger.signature_fields
      ])
      for detector_class, detector_triggers in group_by(triggers, "detector_class")
  },
  "topology_signature": sha8(sorted_topic_set_with_qos_class),
}
```

`normalize(v)` rounds floats to the detector-declared precision and
strips host/session/run-specific identifiers. The sha16 of the
canonical-JSON encoding is the `fingerprint_id`.

Why this works before fancy ML:
- Two incidents with the same detector classes firing on the same
  subsystems and topics will collide. That is exactly what we want.
- Detectors with high false-positive rates can declare narrower
  `signature_fields` to keep the fingerprint robust.

Why this is honest:
- It will *over-cluster* when two unrelated failures happen to fire
  the same detectors. We surface the cluster size and let the user
  reject. We never pretend to know cause from fingerprint alone.

### E. Prevention loop

After an incident is built, the report includes a *recommended*
preflight rule. The user opts in:

```
robot-blackbox prevention adopt --from-incident inc_2026-05-07T14-22-13_a3f2
```

This writes a new YAML to `~/.blackboxrs/prevention/rules/`. The user
can edit, disable, or delete it. Rules are versioned by file; a rule
can also be hand-authored without a source incident
(`robot-blackbox prevention add --check topic_present --topic /scan`).

Preflight runs as a separate command (`robot-blackbox preflight`) so
it can be wired into a robot's launch shell script independently of
the daemon. Default exit codes:
- 0: all checks pass.
- 1: at least one blocking check failed.
- 2: warnings only.

When the daemon detects a recurrence (a new trigger matches a
fingerprint that has a `PreventionRule`), it logs a `prevention.miss`
event with the rule id. Fix-the-fix telemetry.

---

## 5. Backward compatibility

- Existing `BlackBoxEvent` schema and JSONL format are **not changed**.
- Existing `start / stop / status / dump-log / replay` CLI commands
  keep working.
- New CLI surface is purely additive: `incident`, `preflight`,
  `prevention`.
- Existing config keys remain valid; new config sections (`incident`,
  `prevention`) are added with sensible defaults.

## 6. Open questions (intentional)

- **Where do attachments come from for incidents that did *not* trigger
  the rosbag2 recorder?** v0.4: the bundle does not include a bag; the
  user can attach one manually with `incident attach <bundle> <bag>`.
- **How do we handle multi-process robots?** v0.4: out of scope. The
  incident format already carries `host`; multi-host aggregation is a
  forwarder problem, not a schema problem.
- **What about distributed clocks / time skew?** v0.4: we trust local
  UTC and document this. v0.5 will add NTP-skew detection in
  `system_monitor` and a corresponding `TimelineEvent` annotation.
